Setup · both apps

Install it in under a minute

Same plugin either way. Pick the column that matches the app you use — Claude Code is the terminal, Cowork is the desktop and web app.

Claude Code

Terminal

Run these two commands in any session:

/plugin marketplace add Cloudscockpit/actionboard-build-mission-pipeline
/plugin install actionboard-v5-agentformation@actionboard-v5-agentformation

If the install summary says Run /reload-plugins to activate., run /reload-plugins. Otherwise it is already live.

Confirm it loaded:

claude plugin details actionboard-v5-agentformation@actionboard-v5-agentformation

Claude Cowork

No terminal

This happens in the interface, not the chat box — typing the command above into a Cowork message will not work.

  1. Open Customize in the sidebar, then Plugins.
  2. Select Add marketplace and enter
    Cloudscockpit/actionboard-build-mission-pipeline
  3. Find ActionBoard V5 AgentFormation in the list and select Install.
  4. Open the installed plugin to review its skills and agents before enabling them.
Then, in either app: type /start-mission followed by what you want done, in plain English. You will get the four tables above and a prompt to approve. Nothing is written until you reply go.
Extending · new skills

Teaching the Agents something new

A skill is a folder with one Markdown file. The Agents pick it up automatically once it is registered in the actions map. There are two ways in, depending on whether you want the skill for this mission or for good.

Option A — let ActionBoard V5 build it mid-mission

During Skills Gap analysis, any capability with no registry match is flagged needs-new-skill. ActionBoard V5 asks before creating anything: 

Skills Gap includes 1 new skill: pdf-extraction.
Want me to scaffold it via skill-creator now? (yes / no / skip <name>)

Answer yes and it scaffolds the skill through skill-creator. The new skill becomes available next session, or immediately after /reload-plugins. Good for one-off gaps; it lives in your own skills directory, not in the plugin.

Option B — ship it inside the plugin

Fork the repo and add the skill properly, so it travels with the plugin for every user. Six steps, in order.

Create the folder and SKILL.md

The folder name and the name: in the frontmatter must match exactly. If they differ, the skill is skipped silently — no error, it simply never appears. 

skills/changelog-writer/SKILL.md

---
name: changelog-writer
description: Write a release changelog from merged commits,
  grouped by type. Use when the user asks to "write the
  changelog", "what shipped this release", or at the end
  of a mission that touched multiple features.
---

# Changelog Writer

Read the commit range, group by type, write to CHANGELOG.md.
...

Write the description like a trigger, not a summary

The description is the only thing Claude sees when deciding whether to fire the skill. Include the literal phrases a person would actually type. "Writes changelogs" will not trigger; the version above will.

Register it in the actions map

Add an entry to skills/skills-registry/actions-map.json. This is what Black Agent consults during Skills Gap analysis — an unregistered skill exists but never gets planned into a mission. 

{
  "action": "changelog-authoring",
  "agent": "yellow-agent",
  "description": "Write a release changelog from merged commits",
  "requiredTools": ["Read", "Bash", "Write"],
  "skills": ["changelog-writer"],
  "status": "covered"
}

Check the tools contract

Every tool in requiredTools must appear in that Agent's frontmatter tools: line. Miss one and the Agent is assigned work it physically cannot do — the mission fails at dispatch, not at plan time. The entry above needs Write added to agents/yellow-agent.md, which ships with Read, Edit, Bash, Glob, Grep.

Verify every entry at once rather than by eye:

python3 - <<'PY'
import json, re, os
agents = {}
for a in os.listdir('agents'):
    fm = re.match(r'^---\n(.*?)\n---', open(f'agents/{a}').read(), re.S).group(1)
    n  = re.search(r'^name:\s*(.*)$',  fm, re.M).group(1).strip()
    tl = re.search(r'^tools:\s*(.*)$', fm, re.M)
    agents[n] = {x.strip() for x in tl.group(1).split(',')} if tl else None

for a in json.load(open('skills/skills-registry/actions-map.json'))['actionTypes']:
    have = agents.get(a['agent'])
    if have and (miss := set(a['requiredTools']) - have):
        print('MISSING', a['action'], '->', a['agent'], sorted(miss))
PY

Reference bundled files by plugin root

If the skill reads anything shipped alongside it — a template, a knowledge-base doc — address it through ${CLAUDE_PLUGIN_ROOT}. A bare relative path resolves against whatever project the user is in and the read fails. 

✗  Read the format reference at kb/changelog-format.md
✓  Read ${CLAUDE_PLUGIN_ROOT}/kb/changelog-format.md

Bump the version, then validate

Raise version in both .claude-plugin/plugin.json and .claude-plugin/marketplace.json. The version field pins the plugin — users receive an update only when it changes, so a push without a bump sits on GitHub invisibly. 

claude plugin validate .
claude plugin validate .claude-plugin/plugin.json
claude --plugin-dir . -p "list your actionboard-v5-agentformation skills"

The first command resolves the marketplace manifest when both live in one folder, which is why the plugin manifest gets its own line. The third actually loads the plugin and proves the skill registers.

Things that bite

SymptomCause
Skill never appears Folder name and frontmatter name: disagree. They must match character for character.
Skill loads but never fires The description reads like a summary. Put the phrases users actually type into it.
Agent blocked at dispatch A tool in requiredTools is missing from that Agent's frontmatter tools:.
Skill exists but is never planned No entry in actions-map.json, so Skills Gap analysis cannot find it.
File not found at runtime A bundled path written relative instead of through ${CLAUDE_PLUGIN_ROOT}.
Users stay on the old version Pushed without bumping version. The field pins the plugin.
Output

Missions leave a record you can query

Every mission document is written twice — Markdown for people, schema.org JSON-LD for machines. That is the open format Google's Knowledge Graph consumes, so output loads into a graph store with no transform step.

Beyond one mission

ActionBoard.ai runs the Agents as a continuous loop

This plugin gives you one mission at a time, in your editor, on your machine. ActionBoard.ai is the platform the Agents come from — where a single mission becomes an operating loop that keeps running, learns from each pass, and spans local, cloud, and mobile.

The RAOARA loop · six phases

Every ActionBoard run flows through the same six phases, then feeds what it learned back to the start. Where the plugin stops after the mission report, the loop keeps going.

R 01Recognize

Asks clarifying questions until the goal is scoped.

A 02Acquire

Dispatches sub-agents across docs, web, and APIs.

O 03Organize

Shapes raw data into an Action Graph.

A 04Act

Executes — API calls, deploys, writes back.

R 05Review

Audits for accuracy, drift, and policy compliance.

A 06Adapt

Crystallises patterns into scheduled automations.
